# Terminal indexing failures

No-code event indexing now stops the affected event stream on its network when a
log cannot be decoded with the configured ABI, or when a raw PostgreSQL event
value contains NUL in text, a text array, or JSONB. Resolved PostgreSQL custom-table
values are checked too, including values from `$constant(...)` and RPC calls.
Retrying those same inputs
cannot succeed. PostgreSQL binary values can still contain zero bytes.

The callback rejects the batch before making writes or publishing its outputs.
The failed batch does not advance the durable cursor. Previously committed
batches remain committed. With concurrent callbacks, another batch may already
have produced effects before the failure becomes known; stopping it cannot undo
those effects. This change does not make replayed effects idempotent or make
independent PostgreSQL, ClickHouse, CSV and stream writes atomic.

For a resolved PostgreSQL custom-table NUL, the callback stops after preparation
and before staging raw or derived writes. Its tentative receipt claims roll back
too, so correcting the source and restarting can apply the same events. The error
identifies the custom table and column without printing the resolved value. A
schema change cannot make PostgreSQL text or JSONB accept NUL. Binary columns
continue to accept zero bytes.

Other event streams and networks can continue. A dependency group stops when a
prerequisite stream fails. Retryable errors, including existing Rust handlers'
`String` errors and transient storage failures, retain their retry behavior.
Native-transfer and block trace callbacks use the same permanent-error policy.
Because trace handlers on one network share a cursor, a permanent failure stops
that network's trace pipeline before its checkpoint, including empty trailing
ranges. Other trace networks and contract-event streams can continue. Earlier
trace handlers may already have produced effects before a later handler fails;
stopping the pipeline does not undo those effects.

## Monitoring and recovery

When the engine's health server is enabled, a retained terminal callback failure makes
`GET /health` return HTTP 503 with `services.indexing` set to `"unhealthy"`.
`indexing.failed_streams` lists the callback `id`, `indexer`, `contract`, `event`,
`network`, and requested `from_block` and `to_block`. The range identifies the
rejected batch, rather than a guarantee that every block in it contained a bad
event. The field is omitted when there are no recorded failures.

Read the error log for the cause and event identity; the health response does not
include callback error text or event payloads. The failure stays recorded for the
registry's lifetime. Restart indexing after correcting the ABI or choosing storage
that can represent the data. A PostgreSQL schema change cannot make PostgreSQL text
accept NUL. There is no automatic skip, payload rewriting, quarantine, or historical
repair. Review previously indexed history before rebuilding affected data. Health
status does not establish general per-stream freshness or detect every stalled
RPC request or retryable error.

Native-transfer block fetching also requires exactly one response for every
requested block and full transaction objects. Missing or repeated blocks and
hashes-only responses return a fetch error before any block or transfer callback
and leave the cursor unchanged. The processor retries the same range; these
errors do not themselves establish a terminal failure. Complete blocks with an
empty transaction list still succeed. A healthy response does not prove that an
RPC provider has stopped returning incomplete ranges. Review and reindex history
already skipped by an earlier version; this validation does not repair it.

## Rust projects

Run `rindexer codegen typings` to regenerate event and trace registration adapters
before building existing generated projects against the new core. Existing user
handlers keep returning `EventCallbackResult<T>` or `TraceCallbackResult<T>`, both
`Result<T, String>`; these errors remain retryable.

Handwritten engine registration code using `EventCallbackType` or `TraceCallbackType` now returns
`CallbackExecutionResult<T> = Result<T, CallbackError>`. Convert a retryable
`String` error with `.map_err(Into::into)`, or deliberately return
`CallbackError::Permanent(message)` when repeating the callback cannot succeed.
Only declare an error permanent when stopping the stream is the intended policy;
this does not roll back effects already performed by a custom callback.
Both registries' `trigger_event` methods and event/trace-processing config trigger
methods return this typed result too. Propagate or handle it before checkpointing.
`TraceProcessingConfig::trigger_event` no longer invokes callbacks for an empty
input batch; the consumer can still checkpoint a successful empty range. Custom
engine callbacks that relied on receiving empty batches must move that work to
their caller.

Construct event and trace registries with their `new()` or `default()` constructors
and register events with `register_event`. Struct literals are no longer supported
because each registry now owns shared failure state. Clones and `complete()` share
that state. In existing generated `main.rs`, replace an empty
`TraceCallbackRegistry { events: vec![], on_reorg: vec![] }` with
`TraceCallbackRegistry::new()`.
Generated block handlers now also initialize the native-transfer CSV writer in
their shared `TraceContext` when CSV is enabled. This fixes generated-code
compilation; it does not automatically export block rows or add a block CSV format.
Code constructing `health::IndexingStatus` directly must also initialize its new
`failed_streams` field, usually with an empty vector.

For contributors, `make codegen/typings/check` generates the workspace examples in
an offline container and reports drift. `make codegen/typings/update` applies that
output to their existing generated typings directories. Prepare the toolchain and
locked dependencies first using `make dev/image/build` and `make deps/install`.
`make tests/trace-bindings/docker` enables native transfers only in a disposable
copy of the playground, generates its bindings, and compiles that example with
Clippy. It does not change the example's checked-in manifest or generated files.
