# Historic indexing

If you want to index only historic data between block ranges just put in the [start_block](/docs/start-building/yaml-config/contracts#start_block)
and [end_block](/docs/start-building/yaml-config/contracts#end_block) in the YAML configuration file. This will index
only the data between those blocks.

:::info
rindexer will save the last synced block for each contract in the database so it can pick up where it left off if stopped and started again.
If you want to start fresh you can use the [delete](/docs/start-building/delete) command to drop all the data and start over.
You can also use the [drop_each_run](/docs/start-building/yaml-config/storage#drop_each_run) option in the YAML configuration file to drop all the data for the indexer before starting.
:::

```yaml
name: rETHIndexer
description: My first rindexer project
repository: https://github.com/joshstevens19/rindexer
project_type: no-code
networks:
  - name: ethereum
    chain_id: 1
    rpc: https://mainnet.gateway.tenderly.co
storage:
  postgres:
    enabled: true
contracts:
  - name: RocketPoolETH // [!code focus]
    details: // [!code focus]
    - network: ethereum // [!code focus]
      address: "0xae78736cd615f374d3085123a210448e74fc6393" // [!code focus]
      start_block: 18600000 // [!code focus]
      end_block: 18718056 // [!code focus]
    abi: ./abis/RocketTokenRETH.abi.json
    include_events:
    - Transfer
    - Approval
```

Historical fetching validates each nonempty log response against connected block
headers anchored at the requested range end, in both sequential and parallel mode.
A mismatched hash or incomplete header proof retries without dispatching that
response or advancing its checkpoint. Providers must retain the required headers;
this adds header RPC work in bounded batches. Empty responses still cannot prove
that a provider returned every matching event. Upgrading does not repair orphaned
rows or missing intervals already hidden behind committed progress.

# Live indexing

If you want to index live data you can just remove the [start_block](/docs/start-building/yaml-config/contracts#start_block)
and [end_block](/docs/start-building/yaml-config/contracts#end_block) from the YAML configuration file. This will index
from the latest block on the first start, then index new blocks as they arrive.

:::info
Omitting `start_block` does not disable saved progress. When a subscription has a
persisted cursor, restart resumes from its next unfinished block and catches up on
blocks produced during downtime. A new subscription with no saved cursor starts
at the current tip; a subscription without persistent progress does so on every start.

After upgrading from a version that discarded progress without `start_block`,
review each saved subscription cursor and the backlog it will resume. If an older
restart already advanced the cursor across missing history, this change cannot
infer or repair that gap: restore or rebuild the affected interval from verified
canonical history.
:::

```yaml
name: rETHIndexer
description: My first rindexer project
repository: https://github.com/joshstevens19/rindexer
project_type: no-code
networks:
  - name: ethereum
    chain_id: 1
    rpc: https://mainnet.gateway.tenderly.co
storage:
  postgres:
    enabled: true
contracts:
  - name: RocketPoolETH // [!code focus]
    details: // [!code focus]
    - network: ethereum // [!code focus]
      address: "0xae78736cd615f374d3085123a210448e74fc6393" // [!code focus]
    abi: ./abis/RocketTokenRETH.abi.json
    include_events:
    - Transfer

```

# Historic and live indexing

If you want to index historic data and then live data you can put in the [start_block](/docs/start-building/yaml-config/contracts#start_block)
you wish to index the data from and then remove the [end_block](/docs/start-building/yaml-config/contracts#end_block) from the YAML configuration file. This will index
from the block you specified and then index all new blocks as they come in.

:::info
rindexer will save the last synced block for each contract in the database so it can pick up where it left off if stopped and started again.
If you want to start fresh you can use the [delete](/docs/start-building/delete) command to drop all the data and start over.
You can also use the [drop_each_run](/docs/start-building/yaml-config/storage#drop_each_run) option in the YAML configuration file to drop all the data for the indexer before starting.
:::

description: My first rindexer project
repository: https://github.com/joshstevens19/rindexer
project_type: no-code
networks:
  - name: ethereum
    chain_id: 1

storage:
