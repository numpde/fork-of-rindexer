# Changelog

### Breaking changes
-------------------------------------------------
- breaking: PostgreSQL custom-table `database` schema names now fail before startup DDL when they are not valid SQL identifiers. Correct the override before restarting; handwritten Rust exhaustive matches on `GenerateTablesForIndexerSqlError` must handle `InvalidCustomTableSchema`.
- breaking: custom-table `if`/`filter` guards now reject unknown stored `@columns` at manifest validation, including names previously accepted because they matched event fields. Declare the stored column or use `$field` for event data; injected `@network` and `@rindexer_block_timestamp` require a network-scoped table and `timestamp: true`, respectively.
- breaking: contract subscriptions now resume with independent query-keyed checkpoints instead of a shared event/network maximum. Stop writers before the PostgreSQL checkpoint primary-key migration; legacy contract progress is not adopted, so review replay receipts or rebuild affected history. Existing ClickHouse checkpoint tables require a reviewed sorting-key rebuild, and CSV/stream-only queries replay from their configured start with possible repeated deliveries. Handwritten Rust request/cursor structs need `cursor_key`; see [migration instructions](/docs/migrations/postgres-event-replay#independent-subscription-cursors).
- breaking: handwritten `SimpleEventFilter.topics` and `FactoryFilter.topics` values must now be vectors of topic-position arrays; use `vec![old_topics]` for a single predicate. `FilterDetails.indexed_filters` now accepts the complete filter vector; wrap an existing singleton in `vec![filter]`. Fetch integrations must use `topic_sets()` for the full OR union; `topic1()`/`topic2()`/`topic3()` expose only its first alternative. YAML keys and single-filter behavior are unchanged.
- breaking: table-state `@column` conditions now fail manifest validation with ClickHouse, `insert`, or reorg-enabled table networks. Use PostgreSQL `upsert`/`update`/`delete` with reorg handling disabled, or replace the condition with an event-only predicate; the unsupported paths previously dropped guards or could not recover their decisions.
- breaking: PostgreSQL reorg journals now retain each event's sequence and row provenance, store typed values as JSONB, and use BIGINT transaction/log indices. Rebuild existing derived tables and `rindexer_internal.derived_op_log` from canonical history before resuming; old journals cannot restore this missing metadata. ClickHouse reorg configurations using derived `set`, `max` or `min` operations now fail at startup because their journals cannot restore exact values and provenance; use PostgreSQL for those operations.
- breaking: handwritten callers of `native_block_channel` and `native_transfer_block_fetch` must pass the inclusive first unfinished block, rather than the last completed block. Convert saved progress exactly once with checked addition; a fresh start at genesis passes zero directly. YAML `native_transfers.networks[].start_block` remains inclusive and needs no configuration change.
- breaking: `rindexer_sequence_id` now packs 64 block bits, 32 transaction-index bits and 32 log-index bits, preventing collisions/reversed winners at transaction index 1,000. Custom-table events with larger indices stop before writes. Existing derived rows and sequence-bearing journals must be rebuilt or reviewed and migrated with writers stopped; old/new encodings must never be compared. Handwritten `compute_sequence_id` callers must pass checked `u32` indices. See [sequence ordering migration](/docs/migrations/sequence-ordering).
- breaking: required `$call` and `$call_static` failures in no-code table values now fail the callback for retry instead of omitting the operation or substituting a column default. RPC, argument, decoding and accessor failures cannot commit raw events, derived effects, receipts or progress. Deliberate `$null` and unselected `$if` branches retain their behavior. Review/rebuild derived state and receipts affected by earlier silently skipped/defaulted lookups; upgrading does not repair it.
- breaking: non-indexed fixed arrays such as `uint16[2]` and `bytes32[2]` now use array columns instead of scalar columns. Direct nested arrays use PostgreSQL `JSONB` or ClickHouse JSON text in `String` columns, preserving empty and ragged shapes without panics. Stop writers, correct existing schemas and review/rebuild affected history, receipts and derived data before restarting; upgrading does not repair previous data. Rust projects must regenerate typings and review regenerated indexer handlers. See [ABI array storage](/docs/migrations/abi-array-storage).
- breaking: Rust callers of `native_transfer_block_fetch` and `native_transfer_block_processor` must create their paired queue endpoints with `native_block_channel(network, start_after, capacity)` instead of a bare `mpsc<U64>` channel. The shared queue owns planned generations and the first unfinished block; YAML configuration and generated project bindings are unchanged.
- breaking: historical custom-table `$call` lookups now use EIP-1898 `eth_call` with the event block hash and `requireCanonical: true`, and cache raw responses by block identity. RPC providers must support hash-qualified historical calls; custom Rust `ChainProvider` implementations must implement `eth_call_at_hash`. Unsupported selectors pause affected work instead of falling back to a height. Cron calls resolve a header first; fallback timestamps also use its hash. Review/rebuild derived data and application receipts affected by earlier orphaned cache values; duplicate replay alone does not repair them. `$call_static` retains its explicit immutable/latest semantics.
- breaking: provider-operation error displays now begin `Could not complete provider operation` instead of `Could not get block number from provider`, so receipt/log/validation failures no longer falsely report a block-number lookup. Update text-based alert filters that match the old prefix.
- breaking: `native_transfers` now requires full transaction objects and `eth_getTransactionReceipt` responses with explicit execution status and matching transaction/block identity. Reverted value attempts no longer create native events or derived credits. Missing, duplicate, inconsistent or state-root-only receipts pause the range before callbacks or checkpoints; deep history without status receipts needs a later start range or disabled native indexing. Providers must support receipt requests, and indexed historical native results must be reviewed/rebuilt from trusted blocks and receipts, including derived data and application receipts. Native indexing remains opt-in.
- breaking: indexed Solidity arrays and tuples now store their exact 32-byte topic hash in one PostgreSQL `BYTEA` column (ClickHouse uses its existing byte-value `String` representation). They no longer generate array columns or flattened tuple members. Their stream/chat JSON field is the lowercase hash hex without `0x`, matching byte fields. Stop writers and rebuild affected event tables, derived results, receipts and checkpoints from trusted history in a fresh database; existing array/member columns cannot be cast into the original digest. Update SQL/payload consumers and custom-table fields to use `bytes32`, and run `rindexer codegen typings` for Rust projects before restarting. Indexed `string` and `bytes` representations are unchanged.
- breaking: `EthereumSqlTypeWrapper::I64` and `VecI64` now declare PostgreSQL `NUMERIC` and `NUMERIC_ARRAY`, matching existing generated `int40`–`int64` event columns. Handwritten binary COPY to BIGINT columns must supply explicit `INT8`/`INT8_ARRAY` types or use parameterized INSERT. Existing event columns need no type change, but previously corrupted raw and derived history needs reviewed repair with its receipts and progress. See [signed integer storage](/docs/migrations/signed-integer-storage).
- breaking: with network `reorg_handling.enabled: true`, startup now stops if persisted reorg history cannot be loaded, canonical headers cannot be validated, or startup rollback fails. Repair the database/RPC failure and restart; review inconsistent persisted history rather than clearing the window to bypass validation. The former `Using empty window` and `Proceeding without validation` error-path messages are replaced by startup errors. Rust callers with exhaustive `StartIndexingError` matches must handle `ReorgRecovery`.
- breaking: handwritten `FetchLogsResult` literals must include `reorg_generation`, captured with `rindexer::indexer::reorg::reorg_generation(network)` before fetching their logs. The engine now discards batches from an earlier rollback generation before callbacks or checkpoints; generated event bindings need no changes.
- breaking: no-code PostgreSQL custom-table values containing NUL in resolved text, text arrays or JSONB now stop the affected stream instead of retrying forever, including values from `$constant(...)` and RPC calls. Correct the value source or choose storage that can represent it, then restart. The rejected callback makes no raw or derived writes and does not advance its cursor; earlier committed batches remain committed. See [terminal indexing failures](/docs/migrations/terminal-event-failures).
- breaking: managed PostgreSQL native transfers now require application receipts and complete mined identities. Existing native-transfer history without receipts needs a reviewed rebuild or reconciliation; zero-hash placeholder inputs stop the affected stream. Startup renames the internal receipt column `log_index` to `event_position` while preserving existing contract-event receipts; update SQL reading that column. Handwritten `TraceResult::NativeTransfer` literals must supply `trace_address` (`None` for a transaction root, `Some(full_path)` for an internal call); update exhaustive patterns. See [PostgreSQL event replay receipts](/docs/migrations/postgres-event-replay).
- breaking: managed PostgreSQL no-code contract-event indexing now requires event application receipts, including factory, concurrent and mixed-sink configurations. Existing raw history without receipts stops the stream instead of being adopted automatically; stop writers and perform a reviewed rebuild or reconciliation of raw events, derived tables and progress before upgrading. PostgreSQL raw and derived effects now commit together before independent outputs; a later output failure does not roll back that PG group. See [PostgreSQL event replay receipts](/docs/migrations/postgres-event-replay) for scope, recovery and backup requirements.
- breaking: native-transfer and block trace engine callbacks now return `CallbackExecutionResult`, and trace processing stops on permanent errors before advancing its shared network cursor. Regenerate bindings with `rindexer codegen typings`, replace trace registry struct literals in existing `main.rs` with `TraceCallbackRegistry::new()`, and propagate results from handwritten trace config trigger calls. Existing user `TraceCallbackResult` handlers retain retryable `String` errors. Empty trace config batches no longer invoke custom engine callbacks. See [terminal indexing failures](/docs/migrations/terminal-event-failures).
- breaking: no-code ABI decode failures and NUL in raw PostgreSQL text, text arrays or JSONB now stop the affected event stream instead of retrying forever. Correct the ABI or use storage that can represent the data, then restart; failed batches do not advance their cursor. Rust projects must run `rindexer codegen typings`; handwritten event registration callbacks must return `CallbackExecutionResult`, and registry construction must use `new()` or `default()`. See [terminal event failures](/docs/migrations/terminal-event-failures) for recovery, concurrency limits and health API changes.
- breaking: no-code event batches now reject every event in the batch if any log fails to decode with the configured ABI. Correct the ABI or RPC response and restart indexing. Previously skipped history is not repaired automatically and needs a reviewed rebuild.
- breaking: PostgreSQL connections no longer retry with TLS disabled after a TLS, authentication, or connection error. Deployments that relied on this retry must fix the certificate, server, or connection configuration before upgrading; use `DATABASE_URL` with `sslmode=disable` only when plaintext is intentional. The default remains `sslmode=prefer`, which still permits plaintext when the server declines TLS negotiation.
- breaking: PostgreSQL `uint16` event and custom-table columns now use `INTEGER`, and `uint24`/`uint32` use `BIGINT`, with matching array types, to preserve their full unsigned ranges. Before upgrading an existing database, stop writers and widen affected scalar and array columns, including custom-table keys and values; widening alone does not repair previously negative values. Rebuild affected history and derived results from trusted logs. See the [migration guide](/docs/migrations/unsigned-integer-storage).

### Bug fixes
-------------------------------------------------
- fix: PostgreSQL custom-table `database` overrides now select the startup schema and schema-sync destination as well as the write target. Shared declarations schedule identical migrations once, and invalid schema identifiers stop DDL generation. Review data left in the old default schema before restarting; no rows move automatically ([#487](https://github.com/joshstevens19/rindexer/pull/487)).
- fix: custom-table conditions validate parsed references in their actual event or stored-column namespace; valid `@column` guards and quoted string literals no longer require matching event ABI fields ([#488](https://github.com/joshstevens19/rindexer/pull/488)).
- fix: one filtered contract subscription can no longer advance another subscription's restart position; network rollback rewinds all affected query cursors without repeating shared derived reversals.
- fix: all same-event `indexed_filters` alternatives now participate in RPC, shared-tip and HyperSync log fetching; overlapping alternatives deliver each canonical log once, and a failed alternative fails the whole RPC range.
- fix: live indexing with nonzero `reorg_safe_distance` now retries unfinished safe blocks after transient RPC failures instead of stalling behind a reduced retry ceiling ([#484](https://github.com/joshstevens19/rindexer/pull/484)).
- fix: rolling back a `cross_chain: true` table now invalidates only the reorganizing network's journal entries; shared aggregates retain unaffected networks' canonical contributions and wait for concurrent applications before recalculation.
- fix: custom-table `update` and `delete` operations now enforce `if`/`filter` predicates containing `@column` references in PostgreSQL, including mixed event/table predicates.
- fix: PostgreSQL derived `set`, `max` and `min` operations now bind typed recovery values, preserve full `uint256`/`int256` precision and nonnumeric `set` values in JSONB, and abort the application transaction when required journal insertion fails. Rebuild existing derived state and `rindexer_internal.derived_op_log` with the current schema before resuming.
- fix: reorg-enabled historical indexing now captures its recovery tail before writes and keeps detection active until queued callbacks finish, including dependency-ordered events. The persisted original headers survive the historical/live handoff and restart, allowing orphaned raw events and receipts to be replaced. Previously untracked historical tails need a reviewed rebuild; upgrading cannot recover missing original header evidence.
- fix: native transfers now include the configured `start_block` on fresh starts and the first block after saved progress on restart. Publisher, queue and recovery use the same inclusive first-unfinished boundary, including genesis. Review/rebuild native history, derived effects and receipts for previously skipped initial blocks; upgrading does not backfill old gaps automatically.
- fix: reorg recovery now retires callbacks from the old generation before waiting for their writer guards. Active attempts finish before rollback; obsolete callbacks no longer retry enrichment indefinitely or advance progress, and replacement work remains blocked until recovery succeeds.
- fix: `$call` and `$call_static` no longer panic when a tuple value resembles an oversized dynamic return length. Static prefetch and cache hits now honor each expression's explicit `returns (...)` declaration instead of reusing a guessed type. Malformed declared dynamic returns fail decoding without a panic; review and rebuild derived values previously affected by cached type guesses.
- fix: historical log and timestamp retries stay within the failed request and configured `end_block`, including single-block requests. Provider retry hints cannot skip the unfinished prefix. Single-block sequential failures back off instead of expanding into neighboring blocks. Review and rebuild any rows previously indexed beyond your configured endpoint.
- fix: native-transfer queues now retire requests planned before rollback, refetch from the first unfinished block, and checkpoint only a contiguous completed prefix. Historical publishers wait for processing through `end_block` before finishing. Already-queued later requests can no longer advance a rewound cursor past missing replacement history. Review/rebuild history, derived effects and receipts affected by older skipped ranges; upgrading does not repair previous gaps automatically.
- fix: nested tuple fields no longer panic during stream/chat JSON construction before PostgreSQL writes. JSON now consumes the actual flattened leaf values, preserving sibling fields inside and after tuples; existing raw-table columns are unchanged. Previously stalled callbacks can resume after upgrading.
- fix: `bytes1`–`bytes31` values now store their exact declared length in scalar/array columns and tuple-array JSONB, excluding ABI transport padding while preserving logical trailing zero bytes. `bytes32` values and indexed complex-field topic hashes remain 32 bytes. Review and rebuild affected history, receipts and derived results from trusted logs; never repair by trimming trailing zeros. Existing column types are unchanged.
- fix: PostgreSQL tuple-array JSONB values now preserve nested dynamic and fixed arrays at every depth, including empty inner arrays, instead of substituting `null`. Integer values keep their decimal-string representation and existing columns are unchanged. Already corrupted rows and their receipts/derived results require reviewed reindexing from trusted logs; duplicate replay alone does not repair them.
- fix: failed reorg rollback requests now remain pending with the network writer barrier and retry before normal header processing, including when a removed-log or ExEx notification is not repeated. Recovery resumes after transient database or RPC failures clear without requiring another changed header. Pending requests are retained in memory; restart validation remains separate.
- fix: historical backfill with `config.fetch_concurrency` greater than one now keeps delayed workers in their range plan's generation. A worker scheduled after rollback can no longer present an obsolete later range as current and checkpoint ahead of unfinished recovery history.
- fix: a native-transfer publisher behind the network fork now keeps its earlier block-request position when consuming a reorg notification or detecting a reorg itself, so unqueued pre-fork blocks are still requested.
- fix: event-stream reorg recovery now refetches from the earlier of the fork and the stream's first unfinished callback range, including buffered pre-fork logs discarded by the generation fence. Historical, live and dependency event processing retain their own completion boundaries instead of jumping lagging streams to the fork. Previously skipped history still needs reviewed repair.
- fix: PostgreSQL reorg rollback now preserves a stream checkpoint that is already below the fork instead of advancing it to the rollback boundary. Existing gaps created by earlier versions require review or reindexing.
- fix: detect a changed block hash at a retained height even when its parent and the chain tip height are unchanged. One-block live forks now trigger rollback and replacement-history refetch for every affected stream. Previously missed replacements need review or reindexing; the existing parent-mismatch log message is preserved.
- fix: PostgreSQL now stores nonempty signed `int136[]`–`int256[]` event arrays as arrays of decimal strings, preserving element order and signed extrema through INSERT and COPY. Existing VARCHAR array columns and SQL NULL for empty arrays are unchanged; previously failing batches can be retried after upgrading. Scalar bind types now reject these arrays before writing.
- fix: preserve signed `int40`–`int64` values and arrays through PostgreSQL INSERT and COPY with NUMERIC encoding, including negative values and signed extrema. ABI-decoding negative values of these widths no longer panics. Explicit custom-table BIGINT encoding and SQL NULL for empty arrays remain supported; unrelated bind types now fail before writing.
- fix: reorg gap filling, fork detection and rollback now require complete, connected canonical header responses. Missing, repeated or disconnected headers and RPC failures block progress instead of accepting an unvalidated head; complete out-of-order responses remain supported. Live polling retries without accepting the new head.
- fix: fence fetched event batches, native-transfer RPC responses and empty dependency checkpoints against completed network reorgs before writing. Replacement work starts a fresh checkpoint sequence, and batch coalescing preserves generation boundaries. Previously reintroduced orphaned history needs review or reindexing.
- fix: a completed network reorg rollback now rewinds every running event, dependency and native-transfer fetcher on that network, so streams that did not detect the fork also refetch replacement history. Previously missing replacement events require review or reindexing; this does not repair old gaps automatically.
- fix: cancelling a live dependency checkpoint for a block skipped by its logs bloom now releases active-task accounting, so graceful shutdown does not wait for work that was already cancelled. Normal checkpoint completion keeps the same cursor behavior.
- fix: native-transfer block fetching now rejects missing or repeated requested blocks and responses without full transaction objects before running callbacks or advancing the cursor. These RPC failures retry the same range; complete blocks with no transactions still succeed. Previously skipped history is not repaired automatically and requires review or reindexing.
- fix: PostgreSQL factory discovery now accepts already-stored child addresses when a batch is replayed or overlaps another batch, including large batches. Bookkeeping preserves its existing factory/address/network primary key and no longer fails with duplicate-key errors after the raw callback has committed. No schema migration is required; ClickHouse and CSV keep their existing behavior.
- fix: protect managed PostgreSQL native-transfer raw rows and derived operations from duplicate or overlapping replay, including an uncertain COMMIT outcome. Internal calls use their full trace path for receipt identity; native-transfer cursor publication stays with the dispatcher. Missing mined transaction metadata now returns a fetch error before callbacks instead of panicking. Custom Rust callbacks retain their existing replay behavior.
- fix: report failed COMMIT acknowledgements as `rindexer_atomic_batches_total{status="commit_error"}` instead of asserting `rolled_back`; PostgreSQL may already have committed. Pre-COMMIT effect-staging failures still use `rolled_back`. Metric consumers must accept the additional status value.
- fix: commit event receipts with PostgreSQL raw rows and derived changes for no-code contract events, preventing duplicate rows and repeated arithmetic updates after a lost COMMIT response or overlapping replay. Keep cursor publication after other outputs, factory bookkeeping and earlier concurrent callbacks finish; independent outputs retain their own replay semantics. Reorg rollback releases the affected identities transactionally. `INDEXED` counts newly applied PG events, and `rindexer_atomic_batches_total` includes transactions with deferred cursors. Block traces and custom Rust handlers retain their previous PostgreSQL replay behavior.
- fix: generated block trace handlers now initialize the native-transfer CSV writer required by their shared `TraceContext` when CSV storage is enabled. Run `rindexer codegen typings` to regenerate; this does not automatically export block rows or define a new block CSV format.
- fix: retain permanent trace failures across registry clones and per-network dispatch, expose them through the engine's HTTP 503 health response, and stop the affected network's trace processor instead of retrying its rejected range. Trace callback cancellation and failure release active-task accounting without checkpointing; other networks can continue.
- fix: return HTTP 503 from the engine health server after a terminal event callback failure, with affected stream identities and rejected block ranges in `indexing.failed_streams`; omit the field when no streams have failed. Dependent event processing stops on failure, while independent event streams can continue.
- fix: publish event cursor updates in callback dispatch order when `callback_concurrency` is greater than one, including empty trailing ranges. Later callbacks can still execute concurrently, but cannot checkpoint past an unfinished or cancelled predecessor. Cancelled callback tasks now release active-task accounting so they do not hang graceful shutdown. Callback side effects are not made idempotent by this ordering change.
- fix: reject no-code ABI decode failures before storage or derived-table writes instead of silently filtering them out; errors identify the contract, event, network, transaction and log index. Missing log topics return a decode error, and missing required RPC log metadata returns an engine error or fetch retry rather than panicking. Empty batches and optional block timestamps retain their existing behavior.
- fix: enforce PostgreSQL `DATABASE_URL` SSL policy for URI and keyword configurations, including percent-encoded and quoted `sslmode=require` values; a connection error can no longer trigger an application-level plaintext fallback.
- fix: preserve `uint16` and `uint32` values above the signed integer boundary in PostgreSQL event INSERT and binary COPY, including arrays, and custom-table writes and reorg rollback; signed integer and ClickHouse encodings are unchanged.
- fix: preserve every dynamic `bytes[]` element, including empty elements, when converting decoded events for storage; existing empty-array handling is unchanged. Reindex affected historical ranges to recover previously discarded values.
### Features
-------------------------------------------------
- feat: **Shared tip-block log fetch** - live indexing reads each new tip block once per network with an unfiltered `eth_getLogs` shared by every live stream, which filters it locally, instead of one filtered call per stream per block; a block whose header has a non-zero logs bloom is re-asked while the upstream still answers empty, and a zero-bloom block costs no call. New `networks[].shared_tip_logs` knob (`enabled` default `true`, `empty_retry_deadline_ms` default `7000`, `cache_blocks` default `32`) and the `rindexer_shared_tip_logs_*` metrics. Supersedes the per-stream tip re-ask of 0.43.4; `rindexer_live_tip_empty_logs_total` is removed. Rust-mode projects pick it up after `rindexer codegen typings` (the regenerated `networks.rs` calls `create_client_with_shared_tip_logs`); an existing `networks.rs` keeps compiling, since `create_client` keeps its signature, and keeps the per-stream tip calls.

### Bug fixes
-------------------------------------------------
- fix: **Atomic custom-table writes on the Postgres no-code path**: when Postgres is the sole raw-event sink, custom-table operations (upsert, insert, update, delete), their reorg journal rows, the raw event rows and the last-synced cursor now commit in one transaction; a crash, SIGTERM or deadlock mid-batch no longer leaves table effects (for example balance `add` upserts, or append-only insert rows) applied twice on retry. Multi-row upserts (no-code tables and the `create_batch_postgres_operation!` macro) order rows by their conflict key to avoid lock-order deadlocks within a statement. New metric `rindexer_atomic_batches_total{status,reason}`. The atomic path holds one pooled connection per in-flight batch from BEGIN to COMMIT: size `DATABASE_POOL_SIZE` at or above the number of concurrently indexing events when `tables:` are in use. `Tables::` log lines on this path describe statements staged in the batch transaction and repeat if the batch is retried; the `Failed query:` log line now always includes the SQL body; the `Shutdown - checkpointing block ... (mid-batch)` info line is no longer emitted (nothing is written while rows are resolved, and the `(last block written)` line covers the between-operation case); the atomic raw-insert COPY failure line now reads `Error writing binary data, aborting early: ...`; every Postgres error rindexer renders through its `PostgresError` type (setup, migrations, indexes, relationships, factory sync, table and raw-insert writes) now includes the server message and SQLSTATE on one line (for example `db error: ERROR: deadlock detected (40P01)`). ClickHouse/CSV-alongside, factory and streams/chat configs keep the previous at-least-once behavior.
- fix: reorg recovery now reverses custom-table operations that use `iterate`, including native and PostgreSQL JSONB tuple arrays, typed nested/indexed fields, and paired ERC-1155 `TransferBatch` values; rollback quiesces event writers, PostgreSQL changes are atomic, unequal arrays fail before deletion, and interrupted ClickHouse reversals resume from retained attempt-scoped snapshots.
- fix: live event indexing stalling when a temporary RPC retry ceiling matches the last synced block.

### Features
-------------------------------------------------

- fix: graceful shutdown no longer loops forever ("N active indexing tasks pending" with a huge N) when live indexing skipped empty blocks via the logs-bloom check — the skip path underflowed the active task counter ([#432](https://github.com/joshstevens19/rindexer/pull/432))
- fix: **Atomic [batch + cursor] commit for no-code Postgres event storage — closes the double-index race** — event batches (COPY / multi-row INSERT) and the `rindexer_internal.last_synced_block` cursor were previously committed in separate transactions (the cursor asynchronously, with errors swallowed), so a crash or restart between the two re-fetched and re-inserted already-committed ranges, producing byte-identical duplicate rows (reproducible: rewind a cursor and restart). When **Postgres is the sole raw-event sink and no streams/chat are configured**, the no-code batch and its cursor now commit in ONE transaction: a restart either sees neither (clean re-fetch) or both (resume past the batch). Exclusions keep at-least-once semantics wherever exactness would be unsafe — each keeps the legacy path: **CSV or ClickHouse alongside Postgres** (the cursor must not commit before every sink has succeeded), **streams/chat configs** (messages dispatch after the storage write; a committed cursor plus a crash in that window would drop them instead of re-delivering), **factory discovery events** (child-address bookkeeping persists only after the callback — an atomically committed cursor plus a crash there would permanently skip re-discovery of child contracts), and **`callback_concurrency > 1`** (a later batch's cursor commit can leapfrog an uncommitted earlier batch; the exactly-once contract assumes a single indexer process and serialized commits). The custom-tables shutdown checkpoint no longer advances the event cursor when the atomic path owns it (a SIGTERM mid-table-ops could otherwise skip un-inserted raw rows on restart). A cursor update matching zero rows now distinguishes its two causes: a **missing seeded cursor row rolls the batch back and errors** (committing rows whose cursor can never advance would re-index from the manifest start forever), while a cursor already ahead of the batch (the live loop of the same event committing at head during historical catch-up) commits the rows and correctly leaves the cursor untouched. **Rust-mode generated handlers are unchanged** — they keep the legacy insert because users add their own logic inside those handlers, and a baked-in cursor commit would silently skip that logic on a crash before the handler returns; storage-only handlers can opt in explicitly via the public `insert_bulk_with_cursor` API (newly generated handlers include a hint comment when their config qualifies).

# 0.20.0-beta - 10th July 2025

github branch - https://github.com/joshstevens19/rindexer/tree/release/0.20.0

- linux binary - https://github.com/joshstevens19/rindexer/releases/download/v0.20.0/rindexer_linux-amd64.tar.gz
- mac apple silicon binary - https://github.com/joshstevens19/rindexer/releases/download/v0.20.0/rindexer_darwin-arm64.tar.gz

- windows binary - https://github.com/joshstevens19/rindexer/releases/download/v0.20.0/rindexer_win32-amd64.zip

### Features
-------------------------------------------------
- feat: support reth natively in rindexer https://rindexer.xyz/docs/start-building/create-new-project/reth-mode + https://rindexer.xyz/docs/advanced/using-reth-exex

- Indexing with `eth_getBlockByNumber` for more efficiency (but still retain all debug/trace logic for future options)
- Add tx receipt endpoint as useful prep work for raw transaction indexing option
- Add an ever-so-slightly backpressured queue per "network-event" for super fair scheduling, decreased write contention on the database, and improved memory utilisation, can use 1/4 of memory with no throughput drop in some cases.

### Bug fixes
-------------------------------------------------
- fix: https://github.com/ethereum/go-ethereum/pull/31876 changed max address per logs to 1000 to be aligned with geth

- Use correct provider base which is `AnyProvider` that can handle optimism, rollups, and all evm chain style responses.
- Misc tweaks to optimise how this native transfer fetching is done with batching, and pass rpc provider to allow for better batching in other endpoints
- Remove the permits system entirely, it's had some serious problems with fair distribution (where some events would consistenyl take more permits than others)
- We weren't writing to the db if no events were found in a block range... this was a major problem for highly infrequent events as rindexer wouldn't write the "last seen block", fixed.
- Fixed a pretty major bug with the "optimal log parsing regex" (where the BlockNumber::from_str() wasn't actually parsing the hex, so it silently failed and used sub-optimal fallbacks)
- Fix indexer codegen to use correct names and types, as well as fix formatting problems where rustfmt couldn't parse the nesting we were doing
- Other memory optimisations
